# ANWallet Mobile (Android first)

This folder is a **separate app** from the desktop Electron build. Nothing here replaces or modifies `src/main/main.js`, `package.json` scripts, or the Mac/Windows installer pipeline.

## Recommended approach: Capacitor + SQLite (Android first)

| Option | Reuse UI | Reuse DB logic | Offline SQLite | Export/import | Effort |
|--------|----------|----------------|----------------|---------------|--------|
| **Capacitor (recommended)** | Yes — same HTML/JS pages | Yes — with a thin adapter | Yes — native plugin | Yes — Filesystem + Share | Medium |
| Flutter | No — full rewrite | Rewrite all queries | Yes | Yes | High |
| React Native | No | Rewrite | Yes | Yes | High |
| PWA only | Partial | Needs sql.js | Limited on iOS | Awkward | Not recommended |

**Why not Flutter for “easy”?** Your app has ~59 IPC endpoints, 10+ screens, and complex wallet/order/supplier logic in Node. Flutter means rebuilding all of that. Capacitor keeps the UI you already have.

**Why Android first?** iPhone needs a Mac, Xcode, and an Apple Developer account ($99/year) to install on a real device. Android APK sideloading is straightforward.

## Architecture (desktop stays unchanged)

```
wallet-profit-app/
├── src/                    ← Desktop Electron (unchanged)
│   ├── main/main.js        ← Electron + better-sqlite3
│   ├── db/*.js             ← Business logic + SQL
│   └── render/*.html       ← UI (shared with mobile)
│
└── mobile/                 ← New Capacitor app (this folder)
    ├── www/                ← Built copy of UI + mobile bridge
    ├── android/            ← Generated by `cap add android`
    └── src/
        ├── bridge.js       ← Implements window.api (same as preload.js)
        └── db-adapter.js   ← SQLite via @capacitor-community/sqlite
```

Desktop uses: `preload.js` → IPC → `better-sqlite3`  
Mobile uses: `bridge.js` → `@capacitor-community/sqlite` (same schema, same SQL files)

## Data: offline SQLite + manual share

Same as desktop:

1. **Full backup** — Export Data → `.db` or `.json` (already in `src/db/wallet.js`)
2. **Share file** — WhatsApp, Drive, USB, email
3. **Import on another device** — Import Data → replace or merge

Mobile adds Capacitor plugins:

- `@capacitor/filesystem` — read/write backup files
- `@capacitor/share` — export backup to other apps
- `@capacitor/file-picker` or `@capacitor-community/file-picker` — import backup

**Cross-platform:** Desktop `.json` backup ↔ mobile import works today (same schema). Desktop `.sqlite` ↔ mobile works once both use the same table definitions (already in `src/db/database.js`).

No cloud server required.

## Implementation phases

### Phase 1 — Shell (1–2 days)
- [ ] Capacitor Android project in `mobile/`
- [ ] Copy/sync `src/render/*` into `mobile/www`
- [ ] Load `index.html` in WebView
- [ ] Stub `window.api` so app opens without errors

### Phase 2 — Database adapter (3–5 days)
- [ ] Add `@capacitor-community/sqlite`
- [ ] Port `initDatabase()` schema from `src/db/database.js`
- [ ] Wrap sync API: `run()`, `get()`, `all()`, `transaction()` matching better-sqlite3
- [ ] Point existing `src/db/*.js` modules at adapter via bundler (esbuild/vite)

### Phase 3 — Bridge (3–5 days)
- [ ] Implement all `preload.js` methods in `mobile/src/bridge.js`
- [ ] Replace Electron dialogs with Capacitor file picker / share sheet
- [ ] Multi-window screens (suppliers, dashboard) → in-app routes or secondary HTML pages (same as now)

### Phase 4 — Mobile UX polish (2–3 days)
- [ ] Touch-friendly table scrolling
- [ ] Safe areas, smaller fonts on phone
- [ ] Toters API sync over HTTPS (already works from WebView)

### Phase 5 — iOS (optional, later)
- [ ] `cap add ios` on a Mac
- [ ] Apple Developer signing
- [ ] Same codebase as Android

## What we deliberately do NOT change

- Root `package.json` `start` / `build` / `build:mac` / `build:win`
- `src/main/main.js`
- `electron-builder` config
- Desktop install paths (`Application Support/ANWallet/`)

Mobile has its **own** `mobile/package.json`. Desktop builds ignore `mobile/` entirely (already excluded unless added to `files` — it is not).

## Quick start (when Phase 1 is implemented)

```bash
cd mobile
npm install
npm run sync:ui      # copy render assets from ../src/render
npm run build
npx cap sync android
npx cap open android   # Android Studio → Run on device/emulator
```

Build release APK:

```bash
cd mobile/android
./gradlew assembleRelease
# APK: android/app/build/outputs/apk/release/
```

## Alternative: Android-only native (not recommended now)

Kotlin + Room/SQLite would perform well but duplicates every screen and every calculation. Only consider this if Capacitor performance becomes a problem (unlikely for wallet row counts).

## Decision summary

**Start with Capacitor on Android.** Keep Electron desktop as-is. Share data via existing export/import. Add iOS later from the same `mobile/` project when you have Mac + Apple account.
